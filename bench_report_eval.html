07结论与建议

  • 速度INT8 全面胜出:推理快 2.85×、端到端快 1.93×、帧率 7.84→12.39 FPS、体积小 43%、rknn 单帧快 2.02×。所有百分位(p50/p95/max)同步领先,尾延迟未恶化。
  • 精度INT8 代价显著:命中率 80.8%→56.5%(−24.3 pp)、平均置信度 0.483→0.384、掩码面积 −21%。根因是量化压低 cls logit,更多框卡在 0.25 阈值下被丢弃。
  • 后处理INT8 后处理反而更慢(22.53 vs 15.49 ms)。numpy 后处理代码相同,差异来自帧数与场景内容,非模型缺陷,但吃掉了部分加速红利(净 e2e 加速 1.93× < 纯推理 2.85×)。
  • 裕量温度/负载远未触顶:NPU core0 峰值仅 31%、各温度区峰值 <42 °C,无热瓶颈,有充足余量支撑更高负载或并发。

选型建议

  • 量产实时部署 → INT8:帧率/体积/功耗优势压倒性,适合产线/巡检的实时裂缝检测。
  • 细弱裂缝场景 → FP16 兜底:对低对比度、细窄裂缝,FP16 保留更高置信度与召回。
  • 找回 INT8 命中率:把 post_cut.py 顶部 OBJ_THRESH 从 0.25 降到 0.15–0.20,配合 NMS 抑制误检,预计可显著回收命中率(代价是少量假阳性)。
  • 进一步释放红利:后处理当前为纯 numpy(DFL/解码/掩码合成),可改用 cv2 优化或下沉到 NPU/可加速算子,把 post 从 22 ms 压下后,端到端有望逼近 1/推理 ≈ 33 FPS 上限。
